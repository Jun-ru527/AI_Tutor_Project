# 核心接口约定（V1.2）

> 2026-11-26 更新：对齐当前实现（`clean_many` 校验、`confidence` 字段、金额约束、拒答规则）。
> 改这份文档前请先确认代码里确实是这样，别写成"应该的样子"。

## 0. 一条铁律：所有函数只返回一种形状

```python
{"ok": True,  "data": 结果, "msg": ""}
{"ok": False, "data": None, "msg": "一句中文提示"}
```

- **`ok=False` 时 `data` 必须是 `None`**。前端只要 `if not r["ok"]` 就能统一处理。
- 函数内部出错**不抛异常**，一律 `try/except` 后返回 `ok=False`。

## 1. 账单字段（6 个 + 1 个可选）

| 字段 | 类型 | 说明 |
|---|---|---|
| `amount` | float \| None | 金额（元）。缺金额时为 `None`，表示草稿 |
| `category` | str | 支出七类：餐饮/交通/购物/居住/娱乐/医疗/其他；收入：工资/兼职/红包/理财/其他 |
| `spent_at` | str | `YYYY-MM-DD` |
| `merchant` | str | 商户，可空 |
| `note` | str | 备注，可空 |
| `type` | str | `收入` / `支出` |
| `confidence` | float \| None | **可选**。模型自评把握 0~1，由 `ai_core` 贴回；`clean_many` 不输出它 |

> `confidence` 是纯附加字段，不影响入库与统计，界面可用来提示"这条把握不大"。

## 2. 金额约束

- 入库要求 **`0 < amount ≤ 1,000,000`**（元）。不满足时 `add_bill` 返回 `False`。
- `amount is None` 表示"还没填"，只能作为草稿渲染，**不能入库**。
- 展示统一保留两位小数；所有聚合在 SQL 侧完成，模型不参与算数。

## 3. 函数清单

**ai_core.py**

| 函数 | 返回 |
|---|---|
| `parse_text(text)` | `{ok, data: list[dict], msg}` |
| `parse_image(image_path)` | 同上（`image_path` 为文件路径） |

两条附加约定：
- 拒答 / 非记账：`ok=False, data=None`，`msg` 是可直接展示的中文话术。
- 校验不通过但有草稿（如缺金额）：`ok=True`，`data` 里是草稿，`msg` 带警告语。

## 4. `clean_many` 的语义（容易踩坑的一节）

- 返回 `{"ok", "data", "msg"}`，**`data` 永远是 list**。
- 校验不通过时，`data` 里**仍可能带着草稿**（例如金额缺失，`amount` 为 `None`）。
- 这与第 0 节「ok=False 则 data=None」冲突，因此 `ai_core._clean_and_shape()` 做了一层映射：
  - 有草稿 → `ok=True`，草稿交给界面，警告放进 `msg`
  - 无草稿 → `ok=False`，`msg` 直接展示
- **改 `prompts.py` 时不要改这个返回形状**，否则 `ai_core` 会静默出错。

## 5. 拒答规则

- 使用**短语匹配**（`REFUSAL_PHRASES`），不是裸关键词。
- 原则：**拦「请求方法」，不拦「记账行为」**。

| 句子 | 结果 | 原因 |
|---|---|---|
| 帮我找个贷款口子 | 拒答 | 命中短语「贷款口子」 |
| 怎么套现 / 教我刷单赚钱 | 拒答 | 命中「怎么套现」「刷单赚钱」 |
| 借给同事小王 200 块 | 放行 | 「借钱」不在短语表里 |
| 刷单被骗了 500 | 放行 | 属于记账行为（「刷单」裸词已改成短语） |
| 信用卡套现手续费 20 元 | 放行 | 同上 |

> 改动词表后，用上表逐条自测：前两条必须拒答，后三条必须放行。
